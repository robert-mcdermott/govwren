# Glossary

Shared vocabulary. Most of these words can be renamed by an adopting organization; the meanings stay the same.

| Term | Meaning |
|---|---|
| **Action** | Something a named person must do by a date: a corrective action, a follow-up, a gap to close |
| **Agent profile** | The extra description carried by an AI system that takes actions: autonomy, tools, identity, limits, and how a person stops it |
| **AI system** | A tool, product, service, or application that uses AI, whether bought, embedded, open source, or built in-house |
| **Attestation** | A dated statement by a named person that something is true: a record is still accurate, or a unit's list is complete |
| **Cadence** | How often a record is revisited, set by its tier |
| **Campaign** | A request to a set of people to attest by a date, with tracking of who has |
| **Catalog** | The list of AI systems the organization has evaluated, with each one's standing and the data it may be used with |
| **Change request** | An owner's declaration that something about a record has changed, which rules judge as material or not |
| **Condition** | A requirement attached to a decision: before use, by a date, or ongoing |
| **Control** | A safeguard the organization has decided to operate, at program scope (once) or record scope (per use case or system) |
| **Crosswalk** | The mapping from controls to the requirements of a framework |
| **Data category** | An unordered tag for a kind of data that carries specific obligations, such as health information |
| **Data class** | An ordered level of data sensitivity, from public to restricted |
| **Decision** | The recorded outcome of a review, with rationale, decider, and conditions. Never edited; only superseded |
| **Decision packet** | The single screen that gathers everything a decider needs |
| **Dossier** | A complete, printable package of everything on record about one use case or system |
| **Event** | One entry in the append-only history: who changed what, when, from what, to what |
| **Evidence** | A file, link, or note that supports a control, condition, or decision, with an owner and an expiry |
| **Exception** | An approved, time-limited departure from a policy, control, condition, or stop |
| **Finding** | A reviewer's conclusion on a review task: no concerns, acceptable with conditions, or objection |
| **Floor** | A rule that sets a minimum tier whatever the total score |
| **Framework** | A published set of requirements, loaded as an optional content pack |
| **Lapsed** | The standing of an approval that passed its end date without a completed re-review |
| **Material change** | A change that the rules say requires a new review |
| **Model** | A specific model and version that an AI system is built on |
| **Owner** | A person named on a record. The accountable owner answers for it |
| **Pack** | A data file of governance content: a program, a framework, a control library, or a risk library |
| **Passive** | Knowing only what people, documents, and deliberate pushes tell it. No scanning, no interception |
| **Program** | An organization's governance configuration: vocabularies, forms, scoring, rules, cadences, and templates |
| **Reference** | A record's permanent, citable key, such as `UC-0142` |
| **Review** | One pass of governance over a record: initial, periodic, change, incident-triggered, catalog evaluation, or retirement |
| **Review function** | An area of expertise that reviews requests, such as privacy or information security |
| **Review task** | One function's part of a review |
| **Risk acceptance** | A named person's recorded acceptance of the remaining risk, required for the highest tiers |
| **Scoring model** | The factors, levels, tiers, floors, and stops that turn answers into a tier |
| **Session** | A meeting of a decision-making body, with its agenda, decisions, and minutes |
| **Stage** | Where the work is: proposed, pilot, in use, paused, or retired. Separate from standing |
| **Standing** | A record's status with governance: draft, in review, approved, lapsed, and so on. Separate from stage |
| **Steward** | A person responsible for a unit's records and its attestations |
| **Stop** | A rule that marks a request as a prohibited use, which cannot be approved without an exception |
| **Tier** | The level of risk assigned to a use case, which decides how it is reviewed and how often it is revisited |
| **Unit** | A node in the organization's hierarchy: a division, department, lab, core, or office |
| **Use case** | What AI is being used for, by whom, on what. The thing that is requested, reviewed, and approved |
| **Vendor** | An outside supplier of an AI system or model |
